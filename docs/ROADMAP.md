## P0 — 正确性与安全

### P0-1 抖音图集类型判定偏弱 —— ✅ 已修（2026-10-02）

修法与验收见 [CHANGELOG.md](CHANGELOG.md) 的「P0-1 / P3-2 修复」段。要点：

- 判据收敛为单一真源 `platforms/douyin/url.py:is_image_album_payload()`，
  `api.py`（yt-dlp 路径）与 `webapi.py`（采集路径）共用。
- 带音频流的图文帖不再被误判为 `VIDEO`。
- 已核实并记录该分类对下载行为的影响：`engines/yt_dlp.py` 只对 `LIVE`
  分支，图集与视频走同一条下载路径，影响面是展示 / 筛选 / `{media_type}`
  目录模板 / MCP 与 REST 的字段语义，**不是**「下载坏掉」。

### P0-2 uifid 是 UUID4 占位

- **现状**：`webapi.py:509` 的 `self._uifid = uuid.uuid4().hex[:16]`。
- **风险**：平台目前未校验，一旦开始校验 uifid 来源会直接 403。
- **验收**：确认 uifid 的真实生成方式（或确认平台不校验并写入文档）。
- **状态（2026-10-03 复核）**：维持。改真生成方式属于提前逆向，当前无信号，
  与 P3-1（`_MSSDK_STRDATA` 等信号）的取舍一致——等它真的开始校验再处理。

**不要为了抽象而抽象**——得先有第三个异常分页形态出现。

## P3 — 观察项（等信号，不等排期）

1. **`_MSSDK_STRDATA` blob 会过期**——随官方 `runtime_bundler_*.js` 升级而失效。
   典型症状：mssdk 200 但 Set-Cookie 缺 msToken → fallback 伪 token → 403 回升。
   **等到真的出现再处理**，提前重逆向没意义。
2. **`DOUYIN_SIGNED_PATHS` 与真实请求的偏离** —— ✅ 已加守卫（2026-10-02）。
   `tests/test_douyin_sign.py` 用 AST 静态扫描抖音包内所有字面量
   `/aweme/v1/web/...` 路径，与白名单求差集，非空即失败。实测当前 26 条
   白名单全部在用、0 条漂移。详见 [CHANGELOG.md](CHANGELOG.md)。
3. **`ruff` 历史遗留 139 处**——不阻断开发，但新代码必须保持 0 新增。
   若某天决定清账，建议单独一个 commit，不要混进功能提交。
   **2026-10-02 复核**：其中 **F401/F811/F841/F821 共 62 处已确认零真实缺陷**
   （F821 的 3 处运行时缺陷已在 0.3.2 修掉，`login_dialog.py` 剩 1 处为设计使然），
   其余是 UP035/UP037/I001 风格项。清账时优先看 F401，它们只是噪音。

4. **注解可求值性**（2026-10-02 新增观察项）——`from __future__ import annotations`
   让注解惰性化，但**任何显式求值**（`typing.get_type_hints()`，进而 FastAPI /
   Pydantic / 内省驱动框架）都会去模块 `__globals__` 里找名字，找不到就 `NameError`。
   项目已踩过两次（`server/deps.py` 的 `Request`、0.3.2 的 `PlatformAdapter` / `Any` / `PIL`）。
   **新增公共 API 时**：若注解里的名字不能在模块顶层 import（循环依赖 / 可选依赖 /
   刻意延迟导入），就必须显式处理，别指望 `__getattr__`——它不参与 globals 查找。
   守卫见 `tests/test_registry_annotations.py`。

## 已评估：不做（含理由）

| 项 | 结论 | 理由 |
|---|---|---|
| **TikTok 下载 / 采集** | 不做 | 需 `curl_cffi` TLS 指纹伪装 + 签名与 UA 强耦合 + 海外出口硬门槛（上游硬编码 `127.0.0.1:10808`），移植量约 740 行；2026-10-03 用户拍板 |
| **xGnarly 签名器** | 不移植 | 上游即为**死代码**（仅类定义 + `__main__` 演示，不在 `encrypt/__init__.py` 导出名单），抖音侧无触发点（M6.59） |
| **`device_id` 生成器** | 不移植 | 上游 `get_device_id()` **无任何调用者**；DouBi 侧 `device_id` 是用户手填可选配置，缺失仅降级空串（M6.59） |
| **Slides / 图集新接口** | 不实装 | 上游 `slides.py` 是空壳；DouBi **已有两条图集路径**，再引入移动端老接口（第二套域名 + 版本号 + 响应结构）是负收益（M6.58） |
