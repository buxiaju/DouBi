主题方案该做到哪一层？

下面用 DouBi 下载页的真实元素（任务行 / 状态徽章 / 进度条）渲染三种深度。请点选一个。

A

亮 / 暗 / 自动 + 主题色调色板

保留现有亮暗двух态，补上「可持久化」和一组强调色（蓝/青/紫/绿/橙/粉）。语义色（运行/完成/失败）跟随亮暗自动换档。改动集中、风险低。

B

命名主题包（推荐）

在 A 之上引入「主题」概念：每个主题是一份完整 token 表（背景层次 / 文字层次 / 语义色 / 圆角 / 密度）。内置 6 套：默认亮、默认暗、深海、莫兰迪、护眼、高对比。用户选主题而非拼参数。

C

B + 用户自定义主题（可导入导出）

在 B 之上开放自定义：用户可改任意 token、存为命名主题、导出 JSON 分享。功能最全，但需要额外的主题编辑器 UI 和校验逻辑。

顺带修掉的现存问题

今天的实际缺陷（已核实）

  • 主题不持久化 —— AppConfig 里没有 theme 字段，设置页保存时刻意跳过它，重启必回 auto
  • 状态色主题无关 —— #127a1f、#c02b2b 在暗背景上偏暗，themeChanged 也不刷新它们
  • 字面量 "gray" 出现 7 次 —— 散落 parse / settings / login_dialog，暗色下对比度不足
  • 只有 download.py 订阅 themeChanged —— 另外 3 个含颜色的文件切主题时不重绘
  • 透明 QSS 重复两份 —— download 与 settings 各写一遍

方案 B 如何一并解决

  • 新增 theme / theme_color 字段进 DEFAULTS 与 AppConfig，走既有 YAML 持久化
  • 语义色改为按当前亮暗从 token 表取值
  • 所有灰字统一走 tokens.text_muted，字面量归零
  • 提供统一 subscribe_theme() 助手，四个页面都接上
  • 透明背景收敛成一个共享函数
